# Mahlah — functional and code review

**Date:** 2026-08-11 · **Reviewed:** `main` @ `33143c9`, package version **0.1.0**
(clean working tree)
**Actioned:** 2026-08-11. All findings implemented; 31 tests (was 4), and CI
now gates them. See the CHANGELOG-equivalent notes in the commit.

**Method:** the app was run against a live Tirzah backend on :8765 — proxy,
`/api/runtime`, `/api/process/*` and a real `POST /api/ask` round trip — and the
pure modules were probed adversarially with temporary vitest files. Every claim
is backed by a run or a probe, reproduced inline.

---

## Part 1 — Functional review

**Baseline:** `npm run typecheck` clean, `npm test` 4/4, `npm run build`
succeeds. CI runs **typecheck and build only** — see F4.

### What works

The full three-channel contract works end to end against a live backend:

```
app                    -> 200
proxy /api/runtime     -> 200
proxy /api/process/*   -> 200
POST /api/ask          -> answer + 8 processEvents + traceId/sessionId/messageId
```

`/api/runtime` returns the live adapter and model set, so the composer dropdowns
genuinely reflect what is installed rather than a hardcoded list.

Two things deserve specific credit.

**The markdown renderer's safety claim holds.** It says output is "React
elements only (never raw HTML), so model output cannot inject markup". Probed
with four attacks, all render as inert text:

```
raw HTML  -> <p>Hello &lt;img src=x onerror=&quot;alert(1)&quot;&gt; world</p>
js link   -> <p>[click](javascript:alert(1))</p>
data: URL -> <p>[x](data:text/html;base64,PHNjcmlwdD4=)</p>
HTTPS://  -> <p>[x](HTTPS://example.com)</p>          (uppercase fails closed)
```

There is no `dangerouslySetInnerHTML` anywhere, and the anchor path allows only
`http://` / `https://` prefixes, so an unrecognised scheme degrades to plain
text rather than becoming a link. For a surface that renders whatever a local
model emits, that is exactly right, and the uppercase case failing *closed*
rather than open is the detail that shows it was thought about.

An unclosed code fence also degrades sensibly — the remaining text is kept
inside the block rather than swallowed.

**The localStorage load path is properly defensive.** It parses inside a
`try`, rejects a non-array, then schema-checks every record and **salvages the
valid ones** instead of dropping the lot, with a comment explaining why. That is
better than most apps manage. Its counterpart, the save path, is not — see M2.

### Functional defects

#### F1. A malformed trace entry crashes the approval surface — **FIXED**

`pendingApproval` reads `last.detail.step_id` without checking that `detail`
exists:

```
trace entry {event:'process.gate.reached', detail:{}}   -> {"kind":"gate","stepId":"","text":"Gate at step ?."}
trace entry {event:'process.gate.reached'}              -> THREW:
    Cannot read properties of undefined (reading 'step_id')
```

The empty-object case was handled; the missing-key case was not. This runs
during render of the Process Bar, so an older or malformed instance takes down
the operator's approve/reject surface — the one control that exists to unblock
paused agentic work, failing exactly when there is something to unblock.

#### F2. Backend outages report a JSON parse error instead of the status — **FIXED**

Five `/api/process/*` write calls use this shape:

```ts
if (!res.ok) throw new Error((await res.json()).detail || `create failed: ${res.status}`)
```

The `||` fallback is unreachable when the error body is not JSON, because the
throw happens *inside* `res.json()`. Probed:

```
502 with an HTML body -> "Unexpected token < in JSON at position 0"
500 with an empty body -> "Unexpected end of JSON input"
400 with {"detail": …} -> "template name taken"        (works as intended)
```

The README promises "API failures surface as an inline banner in the bar (not
silent no-ops)", and they do surface — but a proxy 502 or a backend that died
mid-session, which is the *likeliest* real failure, shows the operator a
JSON-parsing message that reads like a client bug rather than "the backend is
down". Affects `createProcessTemplate`, `startProcessInstance`,
`resolveProcessGate`, `resolveProcessDeviation`, `completeProcessInstance`.

#### F3. The documented `/api/ask` contract is a small subset of what arrives — **DOCUMENTED**

The README documents four keys. The live response carries **30**:

```
activity_log, activity_report, adapter, answer, budget, controller_decision,
conversation_domain_id, exchange_id, focus_node_id, messageId, model, ok,
phase, plan_revisions, processEvents, process_run_id, process_trace,
project_domain_id, query, replies…, requestId, request_plan, retrieval_status,
semantic, semantic_diagnostic, semantic_status, semantic_summary, sessionId,
session_id, traceId, used_node_ids
```

Not a defect — the extra fields are ignored harmlessly, and documenting the
subset the UI consumes is a reasonable choice. Worth noting only because the
README presents it as *the* contract, and several of those fields (`ok`,
`retrieval_status`, `semantic_status`) are exactly the signals a UI would want
if it ever wanted to say "retrieval found nothing" rather than rendering an
ungrounded answer as though it were grounded.

#### F4. CI does not run the tests — **FIXED**

`.github/workflows/ci.yml` runs `npm ci`, `npm run typecheck`, `npm run build`.
It does not run `npm test`, so the vitest suite — the only automated check of
the Process Bar approval logic, which is the human-oversight surface — is
never gated. Mizpah's CI does run its tests; this one drifted.

## Part 2 — Code review

### Medium

#### M1 · `processLogic.ts:22-29` — unguarded `detail` access — **FIXED**

Code side of F1. `String(last.detail.step_id ?? '')` guards a missing *value*
but not a missing *object*.

**Fix:** `const detail = last.detail ?? {}` before use. The function is pure and
already unit-tested, so the case costs one line and one test.

#### M2 · `App.tsx:69-71` — the save path has none of the load path's care — **FIXED**

```ts
useEffect(() => {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(conversations))
}, [conversations])
```

Unguarded, and conversations accumulate with their full message history — there
is no cap on conversation count or message retention anywhere in the file. Once
the store reaches its quota (typically 5–10 MB) `setItem` throws
`QuotaExceededError` inside an effect, and persistence stops. The load path goes
to real trouble to survive corrupt storage; the write that produces that storage
has no equivalent.

**Fix:** wrap in `try/catch`, surface a one-line warning when it fails, and cap
retained history (oldest conversations, or messages per conversation).

**Actioned.** Persistence moved to `src/storage.ts` so its failure paths are
testable at all — the logic was unreachable from a test while it lived inside
the component. Caps at 100 conversations / 200 messages each, retries with the
newest 10 on quota, and surfaces a banner saying which degradation happened
rather than stopping silently.

#### M3 · `api.ts` — the error-body read should not be able to throw — **FIXED**

Code side of F2, five call sites.

**Fix:** one helper —

```ts
async function errorMessage(res: Response, fallback: string): Promise<string> {
  try {
    const body = await res.json()
    return body?.detail || fallback
  } catch {
    return fallback   // non-JSON body: the status is the useful signal
  }
}
```

### Low

#### L1 · `markdown.tsx:11` — inline tokens do not nest across types — **DOCUMENTED**

`INLINE_TOKEN` splits on whole tokens, so `**bold with `code`**` renders the
inner backticks literally. Correct and safe, just limited; worth a line in the
module docstring listing what is deliberately not supported, since the current
docstring reads as a capability list.

#### L2 · README status claims `npm test` covers the Process Bar — **FIXED by F4**

It does — 4 tests — but F4 means CI never runs them, so the claim is true of a
developer's machine and not of the pipeline.

## Comparison with the other estate reviews

Mahlah is the second-best documented frontend in the estate and the only one
that ships a **verified** security property: the markdown renderer does what it
claims under attack, which I tested rather than took on trust.

Its two real defects are the estate's recurring shape once again, in the two
places a UI can least afford them:

- **F1** takes down the approval surface — the human-oversight control — when a
  trace entry is malformed. The failure is loud (a crash) rather than silent,
  which is better, but it lands on the one screen whose job is unblocking work.
- **F2** is the silent-substitution version: the real signal (a 502, a dead
  backend) is replaced by a misleading one (a JSON syntax error). The operator
  is told something, just not the true thing — which is the same pattern as
  Hoglah replacing a real exception with `"Unexpected worker error"`, and Milcah
  replacing an adapter message with `"generation failed"`.

The asymmetry in M2 is worth naming on its own: the code that *reads*
persistence is carefully defensive about corruption, and the code that *writes*
it has no handling at all. Defensive reading plus unguarded writing is a common
shape, and it means the failure surfaces far from its cause.

---

## Suggested order

1. **M1** — one line and one test; it stops the oversight surface crashing.
2. **M3** — the `errorMessage` helper across five call sites, so an outage
   reads as an outage.
3. **F4** — add `npm test` to CI, so the Process Bar logic is actually gated.
4. **M2** — guard the write and cap retained history.
5. **F3, L1, L2** — documentation.

Nothing here is architectural. The three-channel separation is real and works,
the API layer is a clean single module, the renderer is safe, and the whole app
is two runtime dependencies.
